## What reviews and testing found and fixed

Fourth session (2026-11-11), from an independent review of the third session's fixes and plan, checked by reproducing each finding:

- A unit test file that didn't compile was skipped silently: Godot hands back a script that failed to compile rather than null, so its tests vanished and every platform still printed PASS. The runner now fails such a file.
- Godot's JSON parser rounds decimals before the loader can check them, so `4503599627370495.5` loaded as a whole number and `9007199254740991.0` as a different seed; it also reads `00000000000000000000123` as `0`. The reader now refuses decimal notation and leading zeros (D-029).
- The golden runner judged a battle by its final hash, outcome and ticks, never its checkpoints. A battle that clears ends with no aliens on the field, so a mistake in where they walked would have passed everywhere, the phone included. Every checkpoint must now match.
- The native check now names the battle a crashed build stopped on, and shrinks each failure with the build that showed it.
- The sim library was built with NDK 28.1 while the APK's C++ runtime, which Godot ships, comes from NDK 29. Every import still resolved, but the NDK docs advise one NDK, and a missing symbol would have shown only on the phone, as "the sim library didn't load". The library is now built with Godot's NDK, and CI checks each APK's imports (D-030).
- Google's SDKs carry their own open-source notices, the APK holds two components the licenses file missed (LLVM's C++ runtime, OkHttp's Public Suffix List data), and the project's own code has no license yet (Q9). All in `docs/LICENSES.md`.
- If the sim library came from another build, the Sim tests screen would have stayed on "Running…": in Godot 4.7.2 only the script with the compile error reports it, while the scripts that depend on it still load. The screen now asks every sim script and names the ones that fail.
- The new tool tests would have blocked D-008's golden re-record path, `CXX` silently fell back to g++, and one test checked a helper instead of the real sync. All three fixed.
- The AdMob addon's editor and sample assets (2.4 MB: other companies' logos, a font, music) are in the APK although the game doesn't use them. Recorded for M9 in `docs/LICENSES.md`.

Third session:

- The home screen needed the sim library to compile, so if it ever failed to load on a phone the app would have opened blank, with no way to reach the Plugin Lab. Now the Plugin Lab opens regardless, and **Sim tests** says the library didn't load.
- Setting up a used battle again with inputs the C++ core refused left aliens pointing at freed memory. A refused setup now leaves an empty battle, and the core check covers it.
- Godot 4.7.2 crashed on exit when it found the new sim library during a project's first import; `tools/sync_sim.py` now registers it up front (D-027).
- Two Plugin Lab bugs that would only have shown on the phone. On Godot 4.7.2 an Android plugin's singleton doesn't report its Java methods through `has_method()`, so the Play Integrity and push checks would always have failed; the Lab now asks `has_java_method()` too. And a second run of any check could silently drop its own failure message.
- The sign-in check never initialized the Play Games plugin, so it could only time out.
- Godot reinstalls the Android build template on every CI export, which would undo the edit Firebase needs; an export plugin now makes it each time.
- AdMob's addon downloads its binaries itself, unchecked, during headless runs if they're missing; the fetch script now pins them.

## Measured sim speed

The worker CLI reports nanoseconds per alien-tick (one alien's movement in one tick), timed from the first tick to the result record; setup isn't timed. M0's sim only moves aliens; there's no combat yet.

| Sim | Where | ns per alien-tick |
| --- | --- | --- |
| GDScript (until D-026) | CI headless worker, 7 runs on shared GitHub runners | 320 to 870 |
| GDScript (until D-026) | Second Linux machine, headless worker, 3 runs | 460 to 580 |
| C++ | CI headless worker, 7 runs (CI runs 18 to 24) | 5 to 18 (the final hash and result record weigh most in the shortest battles) |
| C++ | Phone | not measured yet: the Sim tests screen shows ns per alien-tick for each golden and for the generated battles together |

D-026 has the raid benchmark behind the switch: with targeting and damage in, C++ replays a 180-second raid with 303 units and towers in 38 to 100 ms, depending on how many units die and how often targets are re-picked. GDScript took 2.2 to 2.5 s written plainly, and 190 to 225 ms after a rebuild for speed once units die.

## Open issues

- **The build prompt's "pure GDScript" sim line.** D-026 moves the battle sim to C++ and proposes new wording for the owner's build prompt doc. `docs/BUILD_PROMPT.md` changes when the doc does.
- **Sim library on Windows and macOS.** CI builds it for Linux and Android only. Opening the client or worker in a Windows or macOS editor needs `tools/build_sim_native.sh` and `sim/aetd_sim.gdextension` extended to that platform first; nothing in M0 needs it.
- **Plugin risks to watch.**
  - Firebase's plugin has one maintainer.
  - The Play Games plugin's Godot Asset Store page marks v3.4.0 "unstable", although GitHub lists it as the latest release. It replaces Android's default uncaught-exception handler as soon as it's in the APK, which could hide crashes from a crash reporter later. An open issue (#105) says its cloud-save calls stop answering; sign-in is unaffected, but check it before using Play Games for saves. The game should also call its `initialize()` at boot, so Google's automatic sign-in starts at launch.
  - Firebase's plugin answers Android permission results by request code 1001, the same code Godot's own `OS.request_permissions()` uses, so the game shouldn't call that while Firebase is in.
  - Each plugin is built against an older Godot (4.5 or 4.7.0). Every Godot API they call exists in 4.7.2 and the build passes, but only the phone run proves them.
- **Before release (M9):** replace AdMob's sample app ID and demo unit with real ones, add the EU consent flow, give push notifications a proper icon, build the credits screen from `docs/LICENSES.md`, and exclude the AdMob addon's editor and sample assets from release exports.
- **Open questions Q1 to Q6 and Q8** in `docs/DECISIONS.md` (Q7 became D-026).
