# M1 PvE slice: plan

**Status, 2026-11-11:** a plan only. M1 code starts when M0 has passed on the owner's phone and merged into `main` (on a new branch, `m1-pve-slice`), and when the owner has answered the questions below. This is the plan of systems, files and tests the working rules ask for before a milestone.

**Scope (build prompt):** one map, 3 towers, 3 aliens, 10 waves, field towers, placeholder art.

**Done when (build prompt):** it holds 60 fps on a low-end phone, and wave pressure is within target. Wave pressure is required damage per second (total wave HP ÷ (spawn time + time in the kill zone)) compared with what the player's credits can buy. The target ratio is 0.4 to 0.6 on early waves, 0.8 to 1.0 on the last wave, and about 1.1 on boss waves.

## Defaults I'll use unless you say otherwise

These are builder calls, logged in `docs/DECISIONS.md` as they land.

- **Map:** portrait, 9 tiles wide and 16 tall, lanes top to bottom with the Core at the bottom. Two ground lanes; the Skimmer's air route is 40% shorter, as the build prompt says. Field towers go on build tiles beside the lanes, one per tile.
- **Targeting:** every tower uses First (closest to the Core). The other three rules arrive with M2's targeting rules.
- **Hits:** a shot lands on the tick it fires; the client draws the projectile for show only. Splash centers on the target's position at that tick.
- **Damage:** the pipeline's steps 1, 3, 5, 6 and 7. The bonus pool (step 2) is empty until M6, raid modifiers (step 4) are PvP only, and the shield step does nothing without shielded aliens.
- **End of a battle:** won when every wave has spawned and none is left. Lost when lives reach 0.
- **Placeholder art, on purpose.** Shapes drawn in code, in the concept boards' colors: dark ground, cyan for you, violet aliens with yellow eyes and a class-colored glow. Each class also gets its own shape, so color is never the only cue.
- **Motion from code, as the build prompt's art direction asks** (no frame-by-frame animation):
  - towers: recoil, muzzle flashes, tracers and pulsing range rings;
  - aliens: walk bob, squash and stretch, and a white hit flash;
  - Plasma Torch hits: splash rings;
  - kills: death pops.

  A 3-second sketch of this look was recorded with Godot's Movie Maker on 2026-11-11 to check it works.
- **Later milestones:** stars, permanent towers from the base layout, the bonus pool and tower tiers. Finished art and audio: the style test after M2, production in M9.

## Order of work

1. Stage config and its tool rules.
2. **A performance spike first.** Build the performance screen with placeholder entities, before any game logic draws, and send an APK so the owner can run it on the low-end phone. 60 fps is the riskiest part of the done-when, so it's measured first, not last.
3. Core state, commands, targeting and damage, with the model learning each rule in the same change, and the fuzz and goldens kept green throughout.
4. The wave pressure tool. Then propose starting credits and kill credits (M1-C) to the owner.
5. The playable loop with placeholder shapes, and the replay test.
6. An APK for the owner's playtest, with the performance screen run again on the real battle.
7. Independent review, then the M1 report.

## What the owner does in M1

Install the M1 APK, play the stage, and send notes on how each wave felt. Run the performance screen on the low-end phone and send a screenshot.

## Risks

- **Model speed.** Once aliens can die, the model has to step tick by tick, which is far slower than M0's closed form. A sketch with only movement and range checks took about 1.25 s for a battle with 300 aliens, 10 towers and 4,800 ticks. So fresh fuzz battles stay small: about 40 aliens, 8 towers and 1,500 ticks, roughly 0.05 s each, or 20 to 60 s for CI's 400. The 40 committed generated battles can be bigger, because they're generated once. Measure the real model before step 3 and adjust the sizes to keep the core job well inside its 15-minute limit.
- **Rendering 300 entities at 60 fps** on a cheap phone. Pool every node from the start, measure on the phone from the first build, and switch to MultiMesh drawing if pooling isn't enough.
- **A view that feeds back into the sim** would break replays. The battle screen only reads core state, and the replay test catches any leak.
- **Owner time.** The questions above block the start, so they're asked now, alongside the M0 phone check.
